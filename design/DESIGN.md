# Scriber 菜单栏面板 · 第一版设计

## 设计目标

会议开始前快速录制，过程中随时知道正在录什么、有没有声音、文件叫什么、会存到哪里。
以用户给出的 Owl 截图为菜单栏与弹出面板形态参考，重点是清晰、美观和随手可用。

## 视觉方案

- Pearl / 背板：#F4F5F8，微透的浅银灰玻璃。
- Paper / 控件：#FFFFFF，以细描边和轻阴影区分层级。
- Ink / 正文：#262B38；Slate / 次级信息：#717887。
- Iris / 电脑声音与选中项：#7067CF；Jade / 麦克风：#399980。
- Record / 录制提示和停止：#DA666A。
- 标题：系统圆角字体，小范围用于 Scriber 品牌；正文：系统字体；时间：SF Mono 等宽数字。
- 面板宽约 390 px，圆角 22 px，菜单栏锚点小尖角，主体一次可看完。

## 结构比较与选择

方案 A：把所有设置、历史和录制控制铺成一个长面板。信息全，但录制操作容易埋在滚动中。
方案 B：录制优先的主面板，保存位置和历史采用面板内子页。选择 B，主操作位置稳定。

视觉记忆点是一组紫色 / 绿色的双声音电平，颜色对应来源，关闭和无声有明确文字状态。其余元素保持安静。
自评：不用大型波形或营销文案装饰录制页；数字时钟承担真实状态职责。与 Owl 的高密度指标面板相比，保留浮层形态，减少需要扫读的信息。

## 交互

- 点击菜单栏图标或使用原型快捷键 Option+R 呼出面板；关闭面板不停止录制。
- 录音页点击主按钮开始；录屏页点击主按钮进入自选区域、窗口或全屏选择，确认后开始。
- 状态、时间、文件名和两个声音来源始终可见。录制过程中可改名、切换声音来源。
- 音频模式至少启用一路声音；视频模式同样按用户“视频要有声音”的要求检查。
- 面板内直接编辑两种模式的保存位置。录视频的两份文件保存在同一个录屏目录。
- 录制中改保存位置作用于下次录制，避免当前录制中途切换目录。
- 停止后显示保存结果，历史按一次录制展示，可预览、改名、查看对应路径。

## 原型边界

HTML / CSS / JavaScript 用于验证 UI。声音电平、媒体文件、保存和播放均为演示数据，不访问麦克风或屏幕，不生成真实录制文件。原型说明放在面板外。
M4A / MP4、配色、默认路径、Option+R、历史按录制配对等属于本轮设计提案，可继续修改。
真实 macOS 应用应使用系统文件夹选择器和系统授权流程；原型用面板内可编辑路径演示。

## 查看

打开 design/index.html，或在仓库运行 python3 -m http.server 8765 --bind 127.0.0.1，然后访问 http://127.0.0.1:8765/design/。
底部状态切换仅用于设计评审，不属于产品 UI。支持 ?state=recording&mode=audio 或 mode=video 直接展示录制状态。
